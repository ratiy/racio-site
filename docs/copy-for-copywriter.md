## 4. Voice & tone — як писати RACIO

### Загальний підхід

- **Короткі речення, числа, конкретика.** Не «ми пропонуємо широкий спектр послуг з безпеки», а «16 інженерів, 15 років, 500+ клієнтів, 23 галузі».
- **Без маркетингового пафосу.** Не «найкращий підрядник з ОП в Україні», а «за 14 років супроводили 300+ перевірок ДСНС». Факти > прикметники.
- **Числа — з підкладкою.** Кожна цифра — з контекстом. Не «500+ клієнтів», а «500+ клієнтів на активному супроводі».
- **Професійна термінологія** — без спрощення. Читач знає що таке НПАОП, ст. 41 КУпАП, ПТМ, категорія ЦЗ.
- **Italic emphasis** (через `<em>` / `_italic_` у markdown) — тільки в заголовках і 1-2 словах на ключовій думці. НЕ використовуємо для виділення цифр (для них є `<b>` / `**bold**`).

### Анти-патерни

- ❌ «Ми допоможемо вашому бізнесу…» — замість → «Закриваємо регуляторну частину безпеки, щоб ви могли займатись своїм бізнесом.»
- ❌ «Індивідуальний підхід до кожного клієнта» — замість → «16 інженерів з досвідом у 20+ галузях — підбираємо спеціалізацію під ваш техпроцес.»
- ❌ «Інноваційні рішення» — замість → «Методологія за ISO 45001 і директивами ЄС.»
- ❌ «Нам довіряють» як самостійна теза — замість → «DHL, Scania, AstraZeneca на супроводі».
- ❌ Emoji (☁️🎯🚀) — не використовуємо взагалі.
- ❌ Калька з російської («виконання робіт», «приймати участь», «оскільки» як «поскольку») — перевіряти редактором української.

### CTA-формулювання

**Primary buttons** (червоні):
- «Отримати прорахунок →»
- «Замовити аудит →»
- «Викликати команду →» (екстрені — розслідування НВ)
- «Підготувати декларацію →»

**Ghost buttons** (прозорі):
- «Дивитись тарифи» / «Подивитись тарифи»
- «Склад пакета»
- «Приклад звіту»

**Inline-лінки в прозі** — природні посилання на суміжні сторінки (labyrinth-rule, §5).

### H1 / заголовки

- H1 — завжди з `<em>` навколо ключового словосполучення (italic Playfair)
- Формула часто «[сервіс] — [ключова відмінність / вигода]»
- Приклади:
  - «Аутсорсинг охорони праці _під ключ_. Від START до FULL.»
  - «Аудит охорони праці: _дізнайтесь про порушення_ до Держпраці.»
  - «Декларація відповідності ДСНС — _щоб почати діяльність_ без штрафів.»

## 5. Labyrinth-внутрішні посилання

**Правило:** жодних «Вам також буде цікаво» / «Suggested for you» блоків. Усі внутрішні посилання ВПЛЕТЕНІ в прозу природно — через контекст, у числах, термінах, ім'ях послуг.

### Приклади вже вплетених посилань (з сервісних сторінок)

- У SEO-prose блоці `autsorsynh`: «…реакція на інциденти, [розслідування НВ](rozsliduvannia-nv.html), юридичний супровід…»
- У numbered-list `audit`: «…після [нещасного випадку](rozsliduvannia-nv.html) чи скарги працівника…»
- У FAQ `deklaratsiia-dsns`: «…для комплексної підготовки — [аудит ПБ](audit-pojejna-bezpeka.html).»

### Бажана щільність

- **Сервісна сторінка (1000-2000 слів):** 8-12 внутрішніх посилань на суміжні сторінки
- **Головна:** 22+ посилань (охоплення всього каталогу)
- **Hub-сторінки тренінгів:** 10-15 посилань
- **Thin-сторінки після розгортання:** 10-15 посилань

### Cross-link правила

- Не всі посилання на `blog.html` — диверсифікуйте на `koryisne.html`, сервісні, `halusi.html`, `kliyenty-ta-keysu.html`
- У FAQ — кожна 2-га відповідь має inline-лінк
- У SEO-прозі (SEO-A блок) — 2-4 inline-лінки на 300-400 слів
- У numbered-list (SEO-B блок) — 1-2 inline-лінки на пункт

## 7. Типовий шаблон блоку-за-блоком для сервісної сторінки

Це скелет для коментування / доповнення копі при роботі зі сервісними лендингами. 13-18 блоків:

1. **Breadcrumb** — стандартний (шлях з меню)
2. **Hero** — H1 з italic + subtitle + 2 CTA + trust chips + SVG
3. **Quick form** — H3 + hint + 3-4 поля + submit button
4. **«Що входить» (6 cards)** — num + H3 + короткий опис
5. **«Для кого / Коли» (2 cards)** — списки з → bullets
6. **SEO-A prose** — 3-4 параграфи з inline-лінками (мета: 300-400 слів)
7. **Process (4-5 steps)** — horizontal timeline
8. **Deliverables** — vertical list з arrows
9. **SEO-B numbered list (5-8 items)** — intro + numbered list + conclusion (мета: 400-500 слів)
10. **KPI strip** (опц.)
11. **Testimonials** — 2 карточки + logos + footer-link
12. **Quiz/calculator** — 5-step wizard
13. **FAQ** — 6-10 питань з inline-лінками
14. **Blog cards** — 3 картки з diversified hrefs
15. **Final CTA** — H2 + коротке речення + 2 кнопки

Відхилення від шаблону для конкретних сторінок — див. `structure-for-designer.md` §5.

## 8. Workflow для копірайтера

1. **Отримати** файл `copy/NN-name.md` для сторінки
2. **Прочитати** поточний текст блок-за-блоком
3. **Виправити**:
   - Typo, граматику, пунктуацію
   - Порушення voice/tone (див. §4 anti-patterns)
   - Нестиковки з бренд-біблією (§6)
   - Відсутні inline-лінки (§5 density)
4. **Додати** (для тонких сторінок):
   - Нові секції за скелетом (§7) або ТЗ у `Фаза 2 — блочна база/<категорія>/<сторінка>.md`
   - Додатковий контент для досягнення цільового обсягу
5. **Передати назад** редаговані файли + список змін
